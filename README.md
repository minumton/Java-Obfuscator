# Java Obfuscator

Курсовой проект: простой обфускатор исходного кода Java. Получает на вход файлы `*.java` и создаёт их копии, в которых классы, методы и переменные переименованы в бессмысленные имена вида `lI1O0`. Обфусцированный код компилируется и работает так же, как исходный.

Техническое задание: [docs/TZ.md](docs/TZ.md). Отчёт по курсовой работе: `docs/Отчет_КР_Обфускатор.docx`. Документация по коду: `docs/javadoc/index.html`.

## Требования

- JDK 17 или новее (проверено на JDK 21).
- Gradle устанавливать не нужно: используется Gradle Wrapper.

## Сборка

Windows:

```
gradlew.bat jar
```

Linux / macOS:

```
./gradlew jar
```

Результат — исполняемый файл `build/libs/java-obfuscator.jar` со всеми зависимостями.

Другие задачи: `gradlew.bat test` — модульные тесты, `gradlew.bat javadoc` — документация в `docs/javadoc`.

## Запуск

Консольный режим:

```
java -jar build/libs/java-obfuscator.jar [-o <каталог>] <путь>...
```

| Аргумент | Назначение |
|---|---|
| `<путь>...` | файлы `*.java` и/или каталоги (просматриваются рекурсивно) |
| `-o`, `--output <каталог>` | каталог результата, по умолчанию `obfuscated` |
| `-h`, `--help` | справка |

Графический режим — запуск без аргументов:

```
java -jar build/libs/java-obfuscator.jar
```

Код возврата: `0` — успех, `1` — ошибка. Лог пишется в консоль и в файл `logs/obfuscator.log`.

## Пример

Обфускация, компиляция и запуск примера из одного файла:

```
java -jar build/libs/java-obfuscator.jar -o out examples/shapes
javac -encoding UTF-8 -d out/classes out/lIIl1.java
java -cp out/classes lIIl1
```

Пример из нескольких файлов с пакетами:

```
java -jar build/libs/java-obfuscator.jar -o out examples/bank
javac -encoding UTF-8 -d out/classes out/bank/*.java out/bank/model/*.java out/bank/service/*.java out/bank/util/*.java
java -cp out/classes bank.lIIll
```

Новое имя главного класса печатается в отчёте (строка `Main -> lIIll`). Имена генерируются детерминированно, поэтому для одних и тех же файлов они не меняются.

Каталог `examples`:

| Пример | Что показывает |
|---|---|
| `simple` | самый короткий пример: один класс с полями и методами |
| `shapes` | один файл: интерфейсы, наследование, вложенные и анонимные классы, record |
| `bank` | несколько файлов в пакетах: импорты, статический импорт, enum, исключения |
| `library` | методы с именами как в JDK (`add`, `size`, `get`, `format`), обобщения, потоки, аннотации |
| `broken` | файл с синтаксической ошибкой — негативный сценарий |

## Что переименовывается

Классы, интерфейсы, перечисления, записи и аннотации (вместе с именем файла), методы, поля, локальные переменные, параметры. Комментарии удаляются.

Не изменяются: метод `main`, методы, переопределяющие методы JDK (`toString`, `run`, `compareTo`...), всё из JDK и библиотек, константы перечислений, элементы аннотаций, имена пакетов. Подробности и причины — в разделе 3.3 технического задания.

Если анализатор не может однозначно определить, на что ссылается имя, это имя не изменяется нигде, а в лог пишется предупреждение. Так результат остаётся компилируемым.

## Возможные проблемы

**Сборка падает с `Unable to establish loopback connection`.** Так бывает в Windows с JDK 19+, если имя пользователя содержит русские буквы: JDK не может создать служебный файл во временной папке. Перед сборкой задайте временную папку без русских букв.

PowerShell:

```
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:\Windows\Temp'
```

cmd:

```
set JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:\Windows\Temp
```

На работу самого обфускатора это не влияет — только на Gradle.

**При запуске окна печатается `WARNING: Unsupported JavaFX configuration`.** Это предупреждение JavaFX о запуске из обычного jar-файла, на работу оно не влияет.

**Ошибка `UnsupportedClassVersionError`.** Программа запущена на старой Java. Проверьте версию командой `java -version`: нужна 17 или новее.

**Графический режим не запускается.** Окно поддерживается в Windows x64, Linux x64 и macOS на процессорах Apple. На остальных системах используйте консольный режим — он работает везде.
